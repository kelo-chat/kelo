# What Kelo may do with each connector

Generated by `tools/connector_effects.py` from the code (do not edit by hand; a test keeps it in step).

In the app, under Connectors → a connector → *What Kelo may do*, the owner sets each **kind** of action (and, below it, each single action) to **allow**, **ask** or **off**. Nothing set means what happens today: reads run, and a change, send or delete asks where its tool asks today. `allow` means no approval card, except for payments, purchases, card and PIN steps, sign-ups and account steps, and anything the privacy guard flags: they keep their own checks always. `ask` means a card every time, even where a standing rule or a task's permission would have allowed it. `off` means the step is not run and the model is told the owner turned it off.

API: `GET/PUT/DELETE /api/connectors/{id}/permissions` (see `server/src/assistant/permissions.py`). Kinds: read, change, send, delete.

## MCP services

| Action id | Label | Kind | Tool |
|---|---|---|---|
| `mcp_list_tools` | List the service's tools | read | `mcp_list_tools` |
| *each tool the server lists* | its annotations or the model's reading | read, change, send or delete | `mcp_call_tool` |

The kind of an MCP tool: the server's own annotations when it gave them (`destructiveHint` → delete, `readOnlyHint` → read), else the connector's manifest (`connector_rules.json`, which can only tighten), else one cached call of the main model that reads the tool's description (read, change, send or delete; also whether it pays or touches an account). Never the words in the tool's name. A tool nothing can tell about is a change that asks.

## Never called or always asked

Whatever the connector's setting, a standing rule or a task's permission says (`server/src/assistant/forbidden.py`). **never**: the call is refused before any request, whoever asks (it would break or hijack Kelo, run arbitrary code on the owner's machine, or mint a new key, token or password that would come back to Kelo). **ask**: the step always shows an Allow/Deny card, and `allow` does not skip it. Class: code, takeover (who can get in), system, data (cannot come back). Methods `*` = every method; paths are matched against the lower-cased, decoded path; a body pattern also has to match the JSON body. The model is not told this list.
