# Signed payment approvals

A payment approval (Allow on a card that spends money) must carry a signature made by a key that lives only in the phone's hardware
keystore (Android Keystore, iPhone Secure Enclave), used behind the fingerprint or face check. A leaked device token alone can no
longer approve a payment, because it cannot make the signature. The approval itself is signed: the message names the approval, the
decision and the moment the card was asked. The amount and the site are not in the message (the card shows them to the user).

Code: `server/src/assistant/approval_sign.py` (pure functions), `api/approvals.py` (the check on the answer route), `api/devices.py`
(the key), `api/profile.py` (the owner's setting). Shared test vectors: `docs/security/approval-sign-vectors.json`, generated by
`server/tests/approval_sign_vectors_gen.py`, checked by `server/tests/test_approval_sign.py`.

## Which approvals are payments

`approval_sign.is_payment(card)` is true for:

- `confirm_purchase` (the purchase card: it carries `payment`), and any card with a `payment` field;
- a browser click the page judged to be the paying click (`commit` = `pay`).

Not payments: denials, every other tool, `purchase_result` (a wrong charge: the card asks to cancel an order, no money moves),
`payment_step_wait` and the PIN steps (they do not answer with Allow), and the messenger buttons (a payment card gets no buttons there).

## Endpoints

- `POST /api/devices/approval-key` `{"alg": "ES256", "public_key": "<base64 SubjectPublicKeyInfo DER>"}` (a signed-in phone; the
  master token gets 403 `no_device`). Stores the key on the calling device. Only P-256 keys are accepted (422 otherwise). When the
  device already has a key, replacing it needs `"sig"`: the old key's signature over `key_message` = UTF-8 of
  `"kelo-approval-key v1\n" + alg + "\n" + public_key` (403 `signature_required` / `bad_signature` otherwise).
- `GET /api/devices`: every row has `"approval_key": true|false`. Removing a device removes its key (the key sits on the device row).
- `POST /api/approvals/{id}` `{"approve": true, "sig": "<base64 DER>"}`: for a payment with `approve: true`:
  - the calling device has a key and `sig` is missing: 403 `{"code": "signature_required"}`;
  - the signature does not verify: 403 `{"code": "bad_signature"}`;
  - in both cases the approval stays open, and the answer can be sent again;
  - the device has no key (an older app): allowed as before, unless the owner's `require_signed_payments` is on, then 403
    `{"code": "signature_required", "detail": {"message": "Approve payments in the Kelo phone app (you may need to update the app)."}}`.
  Denials and other approvals take no `sig`.
- `GET /api/profile` and `PUT /api/profile`: `"require_signed_payments": bool` (default false).

## The signed message

```
UTF-8 of:  "kelo-approval v1\n" + approval_id + "\n" + ("approve" | "deny") + "\n" + str(issued_at)
```

`issued_at` is an integer (Unix seconds) sent with the card: the `approval_request` event and each item of
`GET /api/approvals/pending` carry `"issued_at"`. Signature: ECDSA P-256 with SHA-256, DER encoded, base64 in the `sig` field.
Each approval id is answered once, so a signature is good for one answer; a second answer gets 404.

## Residual risk (owner decision pending)

With `require_signed_payments` off, a device without a key (an older app, or a leaked token of such a device) can still approve a
payment. Turn the setting on once every phone has an approval key. The master token has no key and is refused while the setting is on.

## Apps

Test against `docs/security/approval-sign-vectors.json`: each approval gives the exact message bytes (`message_hex`) and a valid
signature; the two `bad` cases must fail. The file's public key is a test key only.
